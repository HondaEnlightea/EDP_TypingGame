# EDP_TypingGame

E・D・Pを頭文字とする3単語を入力する、文化祭向けのタイピングゲーム。

## 試作の起動方法

Node.js 24系を推奨。この環境ではv24.14.1で動作確認。

```sh
npm ci
npm run dev
```

ブラウザで `http://127.0.0.1:5173/` を開く。起動したターミナルを閉じるとサーバーも終了する。

配布用のビルドを手元で確認する場合：

```sh
npm run build
npm run preview
```

`http://127.0.0.1:4173/` で確認できる。`dist/`にHTML・CSS・JavaScript・ロゴが出力される。ブラウザでHTMLを直接開くのではなく、HTTPサーバーで配信する。初回のパッケージ導入には通信が必要だが、導入後の起動とプレイは外部素材への通信を必要としない。

## 実装済みの試作（1日目）

- TypeScript + Vite + 通常のHTML/CSS。依存バージョンは`package-lock.json`で固定。
- 青・白の画面に既存スロットと同じ青単色のEDPロゴを使用。
- 開始→出題→入力判定→結果→再プレイ。結果からモード選択にも戻れる。
- 60秒チャレンジと、時間制限なしの練習。どちらも途中で「終了」で結果を見られる。
- 3単語をつなげて入力。大文字・小文字は区別しない。スペース・Backspace・記号は不要で、加点やミスに含めない。
- ミスした英字は1ミスとして記録し、入力位置を進めない。正しい文字を入力すれば続行できる。
- 正しい1文字で1点。正確率は「正しい文字数 /（正しい文字数 + ミスした文字数）」。未入力時は未計測の「—」を表示。
- コンボは連続した正しい文字数。ミスで0に戻り、お題をまたいで継続する。結果に最大コンボを表示。
- 最初のお題は短いローマ字の`Egao Dango Pan`。以降は問題集をランダムに一巡し、一巡内では重複しない。次の一巡との境界でも同じお題を連続させない。
- JSONの問題集は36組（ローマ字24組＋従来の12組）。2つのEDP名称を含む。ローマ字問題にはスロットの`Echigo`、`Eikaiwa`、`Dokagui`、`Donguri`も使用。難易度、音、最高記録保存は次の工程。
- 訪問時の見本は暫定的に`ElectricDataProcessing`。E・D・Pだけ青、ほかは灰色の固定配色。左から一文字ずつ軽くポップし、文字の上に小さな青いキラキラが散る。全文を常に表示し、一巡後は間を置いて繰り返す。見本にはグラデーションや背景の発光を使わない。
- 見本と実際の出題は独立して管理する。見本のアニメーションはゲーム開始時に停止し、モード選択に戻ったら再開する。演出オフ、OSの動きを抑える設定、非表示のタブでは停止する。
- 青・シアンの光、文字入力時の発光、完成時のキラキラを実装。特別なEDPの2問は虹色の文字と完成時の虹色の粒子で演出する。結果のスコアにも青い光を添える。
- 画面上部の「演出」で動く演出と発光をオン・オフできる。切り替えても入力を続行できる。OSの動きを抑える設定ではアニメーションと粒子を停止し、静止した配色を使う。
- 計測は開始ボタンを押した時点から。入力欄からフォーカスを外したり別の画面を見たりしても時間は進む。
- 半角英数での1文字ずつの入力を対象にする。IME変換中は案内を表示し、採点しない。長押しの自動リピートと貼り付けは採点しない。
- スコア・時間・ミス・コンボ・お題の進行は再プレイでリセットされる。

## 現在のデザイン方針

最優先は、冗長な表示を削り「お題を見て打つ」という主目的を強調すること。

- 開始画面はお題の見本・モード選択・開始ボタンが中心。ルールは「遊び方」を開いたときに表示する。
- プレイ中のお題と入力の進み具合は、同じ大きな文字列にまとめる。別の入力文字列や入力ボックスを重ねて表示しない。
- 次の文字には下線、入力済みの文字には落ち着いた青、ミスには補助色を使う。お題をクリックすれば入力を再開できる。
- 光の演出は文字の周りに集中させる。粒子は約1秒で消え、画面操作を遮らない。完成時にも次のお題をすぐ入力でき、画面移動・再プレイ・演出オフで残った粒子を消す。
- プレイ中の数値は時間とスコアに絞る。正確率・完成した組数・最大コンボは結果画面で表示する。
- ミスとプレイ時間は結果画面の「詳しい結果」で確認できる。
- 英語の補助見出し、試作バッジ、番号、背景グリッド、囲い、繰り返しの説明文を削除。青と白、文字の大きさ、余白で見せる。

## 既存作品から読み取った方向性

参考：隣接する`EDP_SLOT`の`index.html`とローカルPDF。

既存スロットはEDPの名称を遊びながら覚えてもらう作品で、特別な組み合わせは次の2つ。

- `Echigo Dangerous People`
- `Electronic Data Processing`

タイピング版でもこの2つを中心的なお題にする。既存スロットにはEが5語、Dが7語、Pが6語あるため、初期のお題候補として活用できる。ただし、無作為な組み合わせには意味の通らないものもある。文化祭版では、説明や面白さのある3単語を選んで登録する案を推奨する。

E・D・Pの強調、音や達成演出は、シリーズとして共通化できる要素。赤い筐体はスロットに合わせた配色であり、タイピング版には青単色のEDPロゴに合わせた青・白の近未来デジタル系デザインを提案する。スロットの操作や単一HTML構成は、タイピング版の必須条件とはしない。

## 技術選定案

第一候補は **TypeScript + Vite + HTML/CSS**。画面は通常のHTML要素で作り、入力判定・進行・採点をTypeScriptで実装する。

| 選択肢 | この企画での評価 |
| --- | --- |
| HTML/CSS/JavaScriptのみ | 最も簡単に始められる。小規模なら十分だが、状態や問題データの整合性は別途確認する必要がある。単一ファイルでの配布が必須になった場合の候補。 |
| TypeScript + Vite | 推奨。問題データとゲーム状態を型で確認しつつ、画面・判定・データを分けて短期間で調整できる。開発時にNode.jsとビルドが必要。 |
| React + TypeScript + Vite | 設定画面や履歴画面が多くなる場合には有力。現段階の画面数では追加の構成を持つ必要性が低い。 |
| Phaser | アクションや大量の描画を伴うゲームに寄せる場合の候補。文字入力が中心の現案では通常のHTMLで十分と判断。 |
| Unity/Godotなど | 専用アプリや複雑な演出を求める場合に再検討。4日間のブラウザ展示向けには配布・調整の工程が増える。 |

[Vite公式ガイド](https://vite.dev/guide/)には`vanilla-ts`のひな形がある。これは開発基盤であり、タイピングゲームの機能は含まない。

[Viteの静的配信ガイド](https://vite.dev/guide/static-deploy.html)に沿って、ビルドしたファイルを配信できる。公開先の候補は既存スロットと同じGitHub Pages。会場では、全素材を手元に置き、ローカルHTTPサーバーで起動できる構成を提案する。ネット接続がなくても遊べることを実機で確認する。

この環境ではNode.js v24.14.1が利用可能。試作ではVite 8.3.4・TypeScript 7.0.2・Vitest 5.0.3・Playwright 1.64.0を導入し、依存バージョンを固定した。

## 遊び方とデザインの初期案

- 会場PCと物理キーボードを主対象にする。実際の端末とブラウザは実装開始時に確認する。
- 標準モードは60秒で何組入力できるかを競う。初心者向けに時間制限のない練習モードを設ける。
- お題は3単語に分けて表示し、頭文字E・D・Pを大きく強調する。
- 入力は例に合わせて連結した英字とし、大文字・小文字を区別しない。スペースとShiftの操作を必須にしない。
- 正しく入力した文字、次に入力する文字、ミスを明確に表示する。
- 初期案ではミスしても入力位置を進めず、正しい文字を打つと続行する。
- スコアは正しく入力した文字数を基本にし、短いお題だけが有利になる採点を避ける。正確率と完成した組数も表示する。
- 青・白を主役とする近未来デジタル系のデザインにする。青単色のEDPロゴを中心に、白〜淡い青の背景、青いアクセント、濃い青の本文で構成する。具体的な青の色味は実際のロゴを確認して合わせる。
- 細いグリッド、角を落としたパネル、ゲージ、控えめなシアンの発光でデジタル感を出す。入力する文字は大きく、装飾や発光で読みづらくしない。
- 入力済みの文字、次に入力する文字、未入力の文字は、色に加えてカーソルや下線でも区別する。ミスには補助色と短い表示を使う。
- 正解時の短い音、コンボ、特別なお題の達成演出を付ける。
- 音と演出は切り替え可能にする。読み上げを加える場合も、読み上げの成否でゲーム進行が止まらないようにする。

これらは試作時の出発点。制限時間、採点、難易度は試遊して調整する。

## 問題データの初期案

最初は、Gitで管理するJSONの問題集を使う。サーバーのデータベースは必要になった段階で検討する。

```json
{
  "version": 1,
  "phrases": [
    {
      "id": "echigo-dangerous-people",
      "words": ["Echigo", "Dangerous", "People"],
      "meaningJa": "越後のヤバいやつら",
      "tags": ["edp", "special"]
    },
    {
      "id": "electronic-data-processing",
      "words": ["Electronic", "Data", "Processing"],
      "meaningJa": "電子データ処理",
      "tags": ["edp", "special"]
    }
  ]
}
```

入力対象の文字列は`words`から生成し、二重管理しない。IDの重複、3単語であること、頭文字がE・D・Pの順であること、入力対象が英字のみであることを検証する。

初期問題集は30〜60組を目安とする。難易度はまず合計文字数を基準に分類し、試遊で調整する。単語を独立抽選する方式は追加の遊び方として検討できる。

最高記録を付ける場合は端末内保存から始める。会場PC内の記録と複数端末で共有するランキングは異なるため、共有が必要になった場合は別途設計する。
