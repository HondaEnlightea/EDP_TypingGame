# EDP_TypingGame

E・D・Pを頭文字とする3単語を入力する、文化祭向けのタイピングゲーム。

## 試作の起動方法

Node.js 24系を推奨。この環境ではv24.14.1で動作確認。

WindowsのPowerShellでは、次のように起動する。

```powershell
Set-Location 'C:\Users\Owner\Documents\GitHub\EDP_TypingGame'
npm.cmd run dev
```

ブラウザで `http://127.0.0.1:5173/` を開く。起動したターミナルを閉じるとサーバーも終了する。

初回、または依存パッケージを変更した後は、起動前に一度だけ `npm.cmd ci` を実行する。通常の起動時には不要。

`npm` だけだと、PowerShellが `npm.ps1` を選び、「このシステムではスクリプトの実行が無効になっている」と表示されることがある。このREADMEでは `npm.cmd` を明示して回避する。実行ポリシーの変更や管理者権限は不要。macOS/Linuxでは以下の `npm.cmd` を `npm` に読み替える。

「Port 5173 is already in use」と出た場合は、ゲームがすでに起動していないか、上記URLを開いて確認する。ゲームが開けばそのまま遊べる。起動し直すときは、先に起動したターミナルで `Ctrl+C` を押してから再実行する。

配布用のビルドを手元で確認する場合：

```powershell
npm.cmd run build
npm.cmd run preview
```

`http://127.0.0.1:4173/` で確認できる。`dist/`にHTML・CSS・JavaScript・ロゴが出力される。ブラウザでHTMLを直接開くのではなく、HTTPサーバーで配信する。初回のパッケージ導入には通信が必要だが、導入後の起動とプレイは外部素材への通信を必要としない。

公開先：<https://HondaEnlightea.github.io/EDP_TypingGame/>

GitHubのリポジトリ設定で「Settings → Pages → Build and deployment → Source」を「GitHub Actions」にする。`main`へ変更をpushすると、`.github/workflows/deploy.yml`がNode.js 24で依存関係を導入し、テスト・ビルド後に`dist/`だけを公開する。公開の成否はGitHubの「Actions」で確認できる。手元のコミットはpushするまで公開先へ反映されない。

Jekyll用の公開処理は併用しない。ソースの`index.html`を直接配信するとゲームが動かないため、Viteでビルドした成果物を使う。ロゴ・効果音は成果物に含め、参考PDFはGitにも公開成果物にも含めない。素材の参照先は相対パスなので、`/EDP_TypingGame/`配下で動作する。

公開更新後はページを再読み込みする。古い表示が残る場合は`Ctrl+F5`で再読み込みする。現在の版は訪問時とゲーム開始時に`ElectricDataProcessing`を表示する。

## 実装済みの試作（1日目）

- TypeScript + Vite + 通常のHTML/CSS。依存バージョンは`package-lock.json`で固定。
- 青・白の画面に既存スロットと同じ青単色のEDPロゴを使用。
- 開始→出題→入力判定→結果→再プレイ。結果からモード選択にも戻れる。
- 60秒チャレンジと、時間制限なしの練習。どちらも途中で「終了」で結果を見られる。
- 3単語をつなげて入力。大文字・小文字は区別しない。スペース・Backspace・記号は不要で、加点やミスに含めない。
- ミスした英字は1ミスとして記録し、入力位置を進めない。正しい文字を入力すれば続行できる。
- 正しい1文字で通常1点。`Electric Data Processing`・`Echigo Dangerous People`は10倍の1文字10点（全入力でそれぞれ220点・210点）。ランダム枠で同じ組になった場合も対象。正確率は得点倍率によらず「正しい文字数 /（正しい文字数 + ミスした文字数）」。未入力時は未計測の「—」を表示。
- コンボは連続した正しい文字数。ミスで0に戻り、お題をまたいで継続する。結果に最大コンボを表示。
- 出題は6問で1ループ。1問目は`Electric Data Processing`、4問目は`Echigo Dangerous People`で固定し、2・3・5・6問目はE・D・Pの単語を独立に抽選する。7問目は次のループの1問目になる。再プレイは1問目から。
- 抽選プールは、既存問題集36組の各単語、スロットの語彙（E:5語・D:7語・P:6語）、固定枠の6語を統合する。重複は大文字小文字を区別せず1語として扱い、各プールから等確率で1語ずつ抽選する。固定枠の単語や3単語の組がランダム枠で出ることもある。重複の回避や再抽選は行わない。
- 訪問時の見本は暫定的に`ElectricDataProcessing`。通常はE・D・Pだけ青、ほかは灰色。左から一文字ずつ軽くポップし、その瞬間だけシアンの文字と光になり、元の配色に戻る。文字の上には小さな青いキラキラが散る。全文を常に表示し、一巡後は間を置いて繰り返す。見本にはグラデーションや背景の発光を使わない。
- 見本と実際の出題は独立して管理する。見本のアニメーションはゲーム開始時に停止し、モード選択に戻ったら再開する。演出オフ、OSの動きを抑える設定、非表示のタブでは停止する。
- 青・シアンの光、文字入力時の発光、完成時のキラキラを実装。`Electric Data Processing`・`Echigo Dangerous People`では、正しく入力できた文字だけを赤から紫へ鮮やかな虹色に光らせる。未入力の文字とカーソルは通常の配色を保つ。訪問時の見本には適用しない。結果のスコアにも青い光を添える。
- 新しいお題が出るとき、E・D・Pの頭文字を固定し、それ以外の文字をスクランブルしながら縦にローリングする。文字ごとに複数の記号を巡り、左から順に160〜300msで確定する。入力が追いついた文字は即座に正しい文字を表示し、演出による入力待ちは発生しない。時間は今後の試遊で微調整する。
- お題の3単語をすべて入力できたとき、通常は`public/Quiz-Ding_Dong04-4(Single).mp3`を1回再生する。`Electric Data Processing`と`Echigo Dangerous People`の完成時、および開始・終了時は`public/Quiz-Ding_Dong04-1(Short).mp3`を使う。成功音は次のお題ではなく、完成した3単語の組で判定する。ランダム枠で同じ組になった場合もShort。途中の1文字ごとの加点・ミス・無視されるキーには音を出さない。
- お題の3単語を問題データから取得し、その場でまとめて読み上げる。固定の読み上げファイルや対応表は使わない。`src/data/phrases.json`の問題を変更・追加しても音声の再生成は不要。出題時に読み上げを呼び出し、効果音の終了待ちや追加の待ち時間を入れない。
- スピード感を優先し、効果音と読み上げの重なりを許容する。重なりを理由に音や読み上げを途中で切らない。成功音が鳴っている場合は別の音を使用し、再生済みの音だけを使い回す。前のお題を読み上げ中に次へ進んだ場合は最後まで読み、続けて最新のお題だけを読む。途中のお題を待ち行列にためない。
- 通常問題は日本語（ja-JP）、`Electric Data Processing`と`Echigo Dangerous People`は英語（en-US）で読み上げる。英語はスロットの実装に合わせ、端末内のMicrosoft Zira、en-US、その他の英語音声の順に選ぶ。Ziraの読み上げ速度はスロットと同じ0.85。英語音声が一覧にない場合も日本語音声を割り当てず、en-USを指定して端末に選択を委ねる。[音声未指定時の言語に応じた選択](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/voice)はブラウザの機能を使用する。実際の発声開始、声質、利用できる言語は端末の音声エンジンに依存する。
- 画面上部の「音」で効果音・読み上げをまとめてオン・オフできる。終了・再プレイ・モード変更・非表示のタブでは古い音声を停止する。再生が拒否された場合もゲームはそのまま進行する。
- 画面上部の「演出」で動く演出と発光をオン・オフできる。切り替えても入力を続行できる。OSの動きを抑える設定ではアニメーションと粒子を停止し、静止した配色を使う。
- 計測は開始ボタンを押した時点から。入力欄からフォーカスを外したり別の画面を見たりしても時間は進む。
- 半角英数での1文字ずつの入力を対象にする。IME変換中は案内を表示し、採点しない。長押しの自動リピートと貼り付けは採点しない。
- スコア・時間・ミス・コンボ・お題の進行は再プレイでリセットされる。

## 現在のデザイン方針

最優先は、冗長な表示を削り「お題を見て打つ」という主目的を強調すること。

- 開始画面はお題の見本・モード選択・開始ボタンが中心。ルールは「遊び方」を開いたときに表示する。
- プレイ中のお題と入力の進み具合は、同じ大きな文字列にまとめる。別の入力文字列や入力ボックスを重ねて表示しない。
- 次の文字には下線、入力済みの文字には落ち着いた青、ミスには補助色を使う。お題をクリックすれば入力を再開できる。
- 光の演出は文字の周りに集中させる。粒子は約1秒で消え、画面操作を遮らない。完成時にも次のお題をすぐ入力でき、画面移動・再プレイ・演出オフで残った粒子を消す。
- プレイ中の数値は時間とスコアに絞る。正確率・完成した組数・最大コンボは結果画面で表示する。
- ミスとプレイ時間は結果画面の「詳しい結果」で確認できる。
- 英語の補助見出し、試作バッジ、番号、背景グリッド、囲い、繰り返しの説明文を削除。青と白、文字の大きさ、余白で見せる。

主なファイル：

- `src/effects.ts`：入力・完成の光の演出とオン・オフ。

固定枠の6語は`src/prompts.ts`の固定問題から常に抽選プールへ加える。語彙を変更しても固定位置は変わらない。ランダムな3単語には既存の組み合わせの説明文を転用せず、生成した単語をそのまま表示・入力判定・読み上げに使用する。問題や語彙を追加しても音声の生成は不要。

## 既存作品から読み取った方向性

参考：隣接する`EDP_SLOT`の`index.html`とローカルPDF。

既存スロットはEDPの名称を遊びながら覚えてもらう作品で、特別な組み合わせは次の2つ。

- `Echigo Dangerous People`
- `Electronic Data Processing`

タイピング版でもこの2つを中心的なお題にする。既存スロットにはEが5語、Dが7語、Pが6語あるため、初期のお題候補として活用できる。ただし、無作為な組み合わせには意味の通らないものもある。文化祭版では、説明や面白さのある3単語を選んで登録する案を推奨する。

E・D・Pの強調、音や達成演出は、シリーズとして共通化できる要素。赤い筐体はスロットに合わせた配色であり、タイピング版には青単色のEDPロゴに合わせた青・白の近未来デジタル系デザインを提案する。スロットの操作や単一HTML構成は、タイピング版の必須条件とはしない。

## 技術選定案

第一候補は **TypeScript + Vite + HTML/CSS**。画面は通常のHTML要素で作り、入力判定・進行・採点をTypeScriptで実装する。

| 選択肢 | この企画での評価 |
| --- | --- |
| HTML/CSS/JavaScriptのみ | 最も簡単に始められる。小規模なら十分だが、状態や問題データの整合性は別途確認する必要がある。単一ファイルでの配布が必須になった場合の候補。 |
| TypeScript + Vite | 推奨。問題データとゲーム状態を型で確認しつつ、画面・判定・データを分けて短期間で調整できる。開発時にNode.jsとビルドが必要。 |
| React + TypeScript + Vite | 設定画面や履歴画面が多くなる場合には有力。現段階の画面数では追加の構成を持つ必要性が低い。 |
| Phaser | アクションや大量の描画を伴うゲームに寄せる場合の候補。文字入力が中心の現案では通常のHTMLで十分と判断。 |
| Unity/Godotなど | 専用アプリや複雑な演出を求める場合に再検討。4日間のブラウザ展示向けには配布・調整の工程が増える。 |

[Vite公式ガイド](https://vite.dev/guide/)には`vanilla-ts`のひな形がある。これは開発基盤であり、タイピングゲームの機能は含まない。

[Viteの静的配信ガイド](https://vite.dev/guide/static-deploy.html)に沿って、ビルドしたファイルを配信できる。公開先の候補は既存スロットと同じGitHub Pages。会場では、全素材を手元に置き、ローカルHTTPサーバーで起動できる構成を提案する。ネット接続がなくても遊べることを実機で確認する。

この環境ではNode.js v24.14.1が利用可能。試作ではVite 8.3.4・TypeScript 7.0.2・Vitest 5.0.3・Playwright 1.64.0を導入し、依存バージョンを固定した。

Microsoftの[完成サンプルの入力処理](https://github.com/microsoft/Web-Dev-For-Beginners/blob/main/4-typing-game/solution/index.js)では、完了時に無効化した入力欄を開始処理で再度有効にしていない。[HTML](https://github.com/microsoft/Web-Dev-For-Beginners/blob/main/4-typing-game/solution/index.html)にも重複したbody要素と外部CDN参照がある。教材をそのまま展示用の完成品として使うには修正が必要。

結論：**Viteの`vanilla-ts`を土台に、EDP専用のゲームを実装する**案を推奨する。上記の小さな実装例を参考にし、コードを取り込む場合は元の著作権表示・ライセンスを保持する。

## 遊び方とデザインの初期案

- 会場PCと物理キーボードを主対象にする。実際の端末とブラウザは実装開始時に確認する。
- 標準モードは60秒で何組入力できるかを競う。初心者向けに時間制限のない練習モードを設ける。
- お題は3単語に分けて表示し、頭文字E・D・Pを大きく強調する。
- 入力は例に合わせて連結した英字とし、大文字・小文字を区別しない。スペースとShiftの操作を必須にしない。
- 正しく入力した文字、次に入力する文字、ミスを明確に表示する。
- 初期案ではミスしても入力位置を進めず、正しい文字を打つと続行する。
- スコアは正しく入力した文字数を基本にし、短いお題だけが有利になる採点を避ける。正確率と完成した組数も表示する。
- 青・白を主役とする近未来デジタル系のデザインにする。青単色のEDPロゴを中心に、白〜淡い青の背景、青いアクセント、濃い青の本文で構成する。具体的な青の色味は実際のロゴを確認して合わせる。
- 細いグリッド、角を落としたパネル、ゲージ、控えめなシアンの発光でデジタル感を出す。入力する文字は大きく、装飾や発光で読みづらくしない。
- 入力済みの文字、次に入力する文字、未入力の文字は、色に加えてカーソルや下線でも区別する。ミスには補助色と短い表示を使う。
- 正解時の短い音、コンボ、特別なお題の達成演出を付ける。
- 音と演出は切り替え可能にする。読み上げを加える場合も、読み上げの成否でゲーム進行が止まらないようにする。

これらは試作時の出発点。制限時間、採点、難易度は試遊して調整する。

## 問題データの初期案

最初は、Gitで管理するJSONの問題集を使う。サーバーのデータベースは必要になった段階で検討する。

```json
{
  "version": 1,
  "phrases": [
    {
      "id": "echigo-dangerous-people",
      "words": ["Echigo", "Dangerous", "People"],
      "meaningJa": "越後のヤバいやつら",
      "tags": ["edp", "special"]
    },
    {
      "id": "electronic-data-processing",
      "words": ["Electronic", "Data", "Processing"],
      "meaningJa": "電子データ処理",
      "tags": ["edp", "special"]
    }
  ]
}
```

入力対象の文字列は`words`から生成し、二重管理しない。IDの重複、3単語であること、頭文字がE・D・Pの順であること、入力対象が英字のみであることを検証する。

初期問題集は30〜60組を目安とする。難易度はまず合計文字数を基準に分類し、試遊で調整する。単語を独立抽選する方式は追加の遊び方として検討できる。

最高記録を付ける場合は端末内保存から始める。会場PC内の記録と複数端末で共有するランキングは異なるため、共有が必要になった場合は別途設計する。

## 開発・検証の進め方案

- 作業ルールを`AGENTS.md`にまとめ、コミット形式とPDF除外を継続して守る。
- 入力判定、タイマー、採点、問題選択を画面表示から分け、重要な境界条件を自動テストする。
- ブラウザでは開始・ミス入力・完了・時間切れ・再プレイを確認する。
- IMEが有効な状態、キーの長押し、入力フォーカスが外れた状態も確認する。
- 最後に会場PCで、画面サイズ・キーボード・音量・通信なしでの起動を確認する。
- PDFの調査にはPDFスキルを使用。画面作成・ゲーム実装・検証に必要な道具を優先し、追加スキルは必要に応じて選ぶ。
